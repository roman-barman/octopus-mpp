- [ ] 1.3 Probe a manual base change on the implementation branch: open a throwaway draft PR `A` to `main` from a branch cut from the implementation branch with one added file, and a throwaway draft PR `B` stacked on `A`'s branch with one more added file; note the "changed files" total of `B`'s first `pr-size` run (expected 1); wait for that run to finish (`gh run watch <id>`), because the concurrency group cancels a run that the next event overtakes; run `gh pr edit B --base main` and verify that a new `pr-size` run for `B`'s branch, created after that command (`gh run list --workflow pr-size.yml --branch <B's branch> --json databaseId,createdAt,conclusion`), reports a "changed files" total larger by at least 1 (it now includes `A`'s file and the implementation branch's files); wait for it to finish; run `gh pr edit B --body ...` and verify one more run is created with the same totals; all three recorded runs must have the conclusion `success`; close both PRs without merging, delete both branches, and record the three run links and their totals in the implementation PR body
- [ ] 1.4 Observe the automatic retarget on the implementation PR itself: after the owner merges the spec PR and GitHub retargets the implementation PR to `main`, make no push, no title or body edit, and no label change on the implementation PR between the merge and this check, since each of them starts a run of its own; verify whether a `pr-size` run was created within two minutes after the merge time and whether its log shows totals that include the spec PR's files (design D4) (`gh run list --workflow pr-size.yml --branch <implementation branch> --json databaseId,createdAt,conclusion` against `gh pr view <spec PR> --json mergedAt`); record the result in the PR body; if no run was created, stop and tell the owner, because the requirement then has to be narrowed to manual base changes before the archive
